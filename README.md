# Hell is Us — чек-лист прохождения

[English](./README.en.md) · **Русский**

**Сайт:** [alexsuslin.github.io/hellisus-cheatsheet](https://alexsuslin.github.io/hellisus-cheatsheet/)

Интерактивный путеводитель по **Hell is Us**, вдохновлённый [Dark Souls 3 Cheat Sheet](https://zkjellberg.github.io/dark-souls-3-cheat-sheet/). Отмечайте пройденные шаги, следите за находками и не пропускайте важные разговоры и благие дела.

## Возможности

- Переключение **русского и английского** на лету, включая инструкции прохождения.
- **Светлая и тёмная темы**: сначала используется тема системы, затем ваш выбор запоминается.
- Маршрут по трём актам, локациям и повторным посещениям.
- Разговоры с NPC, благие дела, загадки, предметы исследований, модули дрона, глифы, реликвии, оружие, защитные предметы, временные петли, хранилища и кепки.
- Предупреждения о действиях, которые можно пропустить навсегда.
- Поиск одновременно по обоим языкам, фильтры по актам и типам, скрытие выполненного.
- Общий прогресс и счётчики по локациям, сохранение в браузере.
- Вкладка **Достижения**: все 40 достижений и дополнительная платина PS5, поиск, фильтры и предупреждения о пропуске.
- Связь достижений с шагами маршрута в обе стороны; отдельные счётчики прохождения и полученных трофеев.
- Экспорт/импорт JSON-копии прогресса и сброс с подтверждением.
- Адаптивная вёрстка, клавиатурная навигация и поддержка сокращённой анимации.
- Статический сайт без серверной части, регистрации, аналитики и внешних шрифтов.

> **Спойлеры:** чек-лист раскрывает события, предметы и решения загадок. В игре нет NG+ и выбора глав. Следуйте предупреждениям до сюжетных переходов.

## Запуск локально

Нужны [Node.js](https://nodejs.org/) **22 или новее** и npm.

```sh
npm ci
npm run dev
```

Откройте `http://127.0.0.1:4173/`. HTML нельзя запускать двойным щелчком: браузер ограничивает загрузку ES-модулей и JSON через `file://`.

```sh
npm test             # Проверки фильтров, сохранения, резервных копий и данных
npm run check        # Форматирование и статический анализ Biome
npm run format       # Применить форматирование
npm run build        # Подготовить статический сайт в dist/
npm run test:browser # Проверить интерфейс в настоящем браузере после сборки
```

Браузерные тесты на Windows используют установленный Microsoft Edge. На Linux/macOS один раз выполните `npx playwright install chromium`. Workflow устанавливает Chromium автоматически и проверяет интерфейс перед публикацией.

Для проверки сайта под путём репозитория:

```sh
node scripts/serve.mjs --dist --subpath
```

Адрес: `http://127.0.0.1:4173/hellisus-cheatsheet/`. Все ссылки на ресурсы относительные: сайт работает и в корне домена, и под именем репозитория.

## Публикация на GitHub Pages

1. Создайте **публичный** репозиторий на GitHub и загрузите проект в ветку `main`. Пример имени: `hellisus-cheatsheet`.
2. Откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**.
3. В **Actions** дождитесь workflow **Check and deploy to GitHub Pages**. Он устанавливает зависимости, проверяет код и данные, собирает сайт и публикует его. Для повторного запуска используйте **Run workflow**.
4. Адрес сайта появится в **Settings → Pages** и в окружении **github-pages**. Для репозитория `alexsuslin/hellisus-cheatsheet` ожидаемый адрес — `https://alexsuslin.github.io/hellisus-cheatsheet/`.

Workflow находится в [`.github/workflows/pages.yml`](./.github/workflows/pages.yml). Pull request запускает проверки, а публикация выполняется только из `main`. Последующие обновления публикуются автоматически при push.

Если вы используете другой аккаунт или имя репозитория, измените ссылку **GitHub** в [`index.html`](./index.html). Сам workflow не привязан к имени репозитория. Для ручной настройки через GitHub CLI:

```sh
gh auth login
gh repo create hellisus-cheatsheet --public --source=. --remote=origin --push
gh api --method POST repos/OWNER/hellisus-cheatsheet/pages -f build_type=workflow
gh workflow run pages.yml
```

Для `--push` нужен хотя бы один коммит. Вместо `OWNER` укажите ваш логин. Если Pages уже включён, создание Pages повторять не нужно.

## Прогресс

При публикации сборка автоматически меняет версии адресов CSS, JavaScript и JSON. Чтобы получить обновление сайта на телефоне, достаточно обычного обновления страницы. Очистка данных браузера не нужна: ключ сохранения и ID шагов и достижений остаются прежними.

Галочки, язык и тема сохраняются в `localStorage` на текущем адресе сайта. Данные не передаются на сервер и не синхронизируются между устройствами. Переключение языка или темы не изменяет галочки.

Перед очисткой данных браузера нажмите **Экспорт прогресса**. Чтобы перенести сохранение, на другом устройстве откройте тот же сайт и выберите **Импорт прогресса**. Импорт заменяет текущие галочки после подтверждения; повреждённые и чужие файлы отклоняются. Если браузер блокирует сохранение, сайт покажет предупреждение, а чек-лист продолжит работать в текущей вкладке.

**Счётчик показывает шаги маршрута, а не количество уникальных коллекционных предметов.** Благое дело или загадка могут включать несколько действий в разных локациях. Один шаг может давать несколько наград и встречаться в нескольких фильтрах. Отмечайте его только после выполнения описанного действия.

Во вкладке **Достижения** выбирайте Steam / Xbox / Epic (40) или PS5 (41 с платиной). Отмечайте **Получено в игре** после фактической разблокировки: сайт не синхронизируется с игровыми аккаунтами. Кнопка **Связанные шаги** раскрывает действия маршрута и их прогресс; нажатие на действие открывает нужную локацию и снимает мешающие фильтры. Обратная кнопка **Достижения** у шага показывает связанные трофеи. Счётчик связанных шагов не является счётчиком уникальных предметов или убийств. Достижения и маршрут входят в общую резервную копию; старые копии маршрута тоже поддерживаются.

## Данные и перевод

[`data/guide.json`](./data/guide.json) содержит весь маршрут. У каждого раздела и шага есть постоянный `id`, переводы `ru`/`en`, категория и ссылка на подробный источник. Меняйте текст без изменения `id`, чтобы сохранённый прогресс оставался привязан к тому же действию. Новому действию нужен новый `id`; переносить старый `id` на другой шаг нельзя.

[`assets/i18n.js`](./assets/i18n.js) содержит интерфейсные переводы. Английские имена некоторых предметов оставлены как ориентир для сопоставления с источником; русские формулировки не заявлены как официальный перевод игры.

[`data/achievements.json`](./data/achievements.json) содержит условия, подсказки, предупреждения, уровни трофеев и связи с маршрутом. Связь задаётся конкретными `route.itemIds` или категориями `route.categories`. Для шести исследовательских тем указаны соответствующие предметы и шаг передачи Тане. Постоянные ID достижений начинаются с `achievement-`; меняйте формулировки, сохраняя эти ID. Русские названия достижений — переводы для удобства, оригинальные имена показаны рядом.
